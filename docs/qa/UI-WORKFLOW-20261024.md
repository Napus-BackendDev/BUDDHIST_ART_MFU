# แผนทดสอบ UI แยกตาม Use Case — 24 ตุลาคม 2569

สถานะ: แผน ยังไม่เริ่มทดสอบ

## ขอบเขต

ทดสอบผ่าน UI จริงบน localhost ทั้ง 3 บทบาท ได้แก่ ผู้ซื้อ (Customer), ผู้เรียน (Artist) และแอดมิน (Admin) รวมถึงผู้เยี่ยมชมที่ไม่ได้ login และ workflow ที่ต่อกันข้ามบทบาท การดูฐานข้อมูล ไฟล์ และ email ทำเพื่อยืนยันผลเท่านั้น ไม่ใช้แทนการกดผ่าน UI การผ่าน unit test หรือ build ไม่นับว่าผ่าน use case

- Frontend `http://localhost:8080`, Backend `http://localhost:8081`
- MongoDB `127.0.0.1:27017/buddhist_art_mfu_uiqa_20261024` clone มาจาก `uiqa_20261016` ไม่แตะ production
- QA login: ปุ่มเลือกบทบาทในหน้า Login แสดงเฉพาะ dev build เปิดได้เมื่อ `NODE_ENV=development`, `QA_LOCAL_LOGIN=true`, DB อยู่ในเครื่อง และ request มาจาก loopback ใน production ต้องตอบ 404
- รูปอัปโหลดจริงเข้า MFU Drive โฟลเดอร์ `qa-ui-20261024`
- Email เข้า SMTP capture `127.0.0.1:1025` ไม่ส่งถึงคนจริง
- Viewport ที่ตรวจ: 375×812, 768×1024, 1440×900
- หลักฐานเก็บที่ `outputs/uiqa-20261024/` (สถานะรายเคสอยู่ใน `state.json`)

## เกณฑ์ผ่านของทุก use case

1. ผลบนหน้าจอถูกต้องทั้งก่อนและหลัง reload
2. ข้อมูลใน DB ตรงกับสิ่งที่กรอก
3. ไม่มี console error และไม่มี network 4xx/5xx ที่ไม่ได้ตั้งใจ
4. ข้อความถูกต้องทั้ง TH และ EN
5. ไม่ล้นจอที่ 375px
6. ถ้ามีไฟล์หรือ email เกิดขึ้น เนื้อหาต้องถูกต้อง

เจอบั๊กให้แก้ทันที เพิ่ม test แล้วทดสอบ use case เดิมผ่าน UI ซ้ำ
